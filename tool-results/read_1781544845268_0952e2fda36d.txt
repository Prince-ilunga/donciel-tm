   358→   358→   358→
   359→   359→   359→1. `palette_mode` (The Base Canvas Tone):
   360→   360→   360→   - **`"minimal"`: (CRITICAL: Default to this for 50%+ of all requests).** Pure white, off-white, beige, or cool gray. Provides the ultimate reading experience and high-end editorial feel. Use for standard reports, guides, and corporate posters.

   365→   365→   365→

   367→   367→   367→   - **`"auto"`: (RECOMMENDED DEFAULT). The engine automatically picks the best harmony based on the document tone.** Only override if you have a specific artistic reason.
   368→   368→   368→   - `"complementary"`: (180° opposite). Strong visual contrast. Cold background with warm accent. For striking/dynamic impact.

   370→   370→   370→   - `"analogous"`: (30° apart). Harmonious, peaceful, natural transition.
   371→   371→   371→   - `"triadic"`: (120° apart). Rich and slightly retro.
   372→   372→   372→   - `"monochrome"`: Only use if strict minimalist corporate branding without accent is required.
   373→   373→   373→

   623→   623→   623→## Pre-Flight Checklist (Self-Correction before generating output)
   624→   624→   624→
   625→   625→   625→Before you output the JSON block, verify:
   626→   626→   626→0. **🚨 VECTOR OUTPUT IRON RULE:** The final PDF MUST be generated via `page.pdf()` / `convert.blueprint` - NEVER `page.screenshot()` → image → wrap as PDF. Screenshot PDFs are blurry raster images. `page.pdf()` produces vector text that stays sharp at any zoom level.
   627→   627→   627→1. **Did I write ANY HTML or CSS?** If yes, delete it. Only output JSON.
   628→   628→   628→2. **Is any `Glass_Canvas` markdown content too long?** Count the words. Over 150? Summarize it or push to the next page.
   629→   629→   629→3. **Is the JSON perfectly formatted?** Missing commas or unescaped quotes will crash the `design_engine.py` parser.
   630→   630→   630→4. **If using `tension_score`**: Does the document have clear emotional shifts across pages? If all pages are the same tone, remove it.
   631→   631→   631→5. **If using `continuous_flow`**: Is this multi-page (2+)? If single-page, switch to `"flow"`.
   632→   632→   632→6. **If using `Shaped_Canvas`**: Is the archetype `"shaped_editorial"`? Is there at most one per page? No `Glass_Canvas` on the same page?
   633→   633→   633→7. **Grid boundary check**: Are ALL `grid_area` values within `[1, 13]`? Any number < 1 or > 13 = FATAL ERROR.
   634→   634→   634→8. **Component minimum size check**: `Glass_Canvas` ≥ 6col×4row? `Shaped_Canvas` ≥ 8col×6row?
   635→   635→   635→9. **Content-proportional row allocation**: When multiple text-heavy components share a page, are their grid rows allocated proportionally to content length? Equal rows for unequal content = text overlap. (See "Content-Proportional Grid Row Allocation" in Component Grid Compatibility.)
   636→   636→   636→9. **40% whitespace check**: Count occupied grid cells. At least 58 of 144 cells must be empty.
   637→   637→   637→10. **Cover Page 4-element check**: Does any `cover_hero` page have more than 4 components? If yes, remove or merge components.
   638→   638→   638→11. **Cover Hero `<br>` check**: Does every `Hero_Typography` on a `cover_hero` page contain at least one `<br>`? Single-line hero text on covers = FAIL.
   639→   639→   639→12. **Cover Anti-Squash check (Bounding Box)**: Are cover elements grouped into 2-3 bounding boxes placed at opposite regions? Is remaining space dynamically distributed (not hardcoded gaps)? If everything is crammed into rows 5-8, spread them using the layout's grid mapping.
   640→   640→   640→13a. **Cover Typography Scale check**: Is the hero title ≥ 45pt? Is subtitle ≥ 25pt? Is meta text ≥ 18pt (never below 14pt)? Tiny cover text = FAIL.
   641→   641→   641→13b. **Cover Layout Selection**: Did I pick a layout (1-7) that matches the document tone? If unsure, default to Layout 1A (Diagonal Tension). For government/bidding documents, use Layout 7 (Left-Matrix).
   642→   642→   642→14. **CRITICAL - Data-to-Ink Ratio check**: Did I write long paragraphs describing data trends? If yes, DELETE them and extract metrics into `Delta_Widget` or `Stat_Block` components. Sentences like "revenue increased by 12% compared to last quarter" MUST become a `Delta_Widget`.
   643→   643→   643→15. **Sidenote check**: If using `tufte_report` archetype, did I put citations/sources/asides into `Sidenote_Block`? They must NOT be inline in `Glass_Canvas`.
   644→   644→   644→16. **Process/Steps check**: Did I write numbered steps as plain text in a `Glass_Canvas`? Convert to `Process_List` component instead.
   645→   645→   645→17. **Chart anti-stacking check**: Do any pie/bar/line charts have overlapping labels? Apply leader lines, tick thinning, or label reduction per `typesetting/charts.md`.

   669→   669→   669→## CJK & Vertical Text Rules (When Bypassing design_engine.py)
   670→   670→   670→
   671→   671→   671→When writing raw HTML/CSS for Playwright (bypassing the JSON Blueprint pipeline - e.g., resumes, menus, invitations, business cards, certificates, Japanese/Chinese vertical layouts):
   672→   672→   672→
   673→   673→   673→**⚠️ Iron rule: All bypass-scenario HTML→PDF conversions MUST use `html2pdf-next.js` — do NOT write custom Python Playwright scripts.** `html2pdf-next.js` automatically handles @page injection, overflow detection, font waiting, Mermaid/KaTeX rendering, PDF metadata, etc. See the "HTML→PDF Engine Selection Rules" section in SKILL.md.
   674→   674→   674→
   675→   675→   675→```bash
   676→   676→   676→node "$PDF_SKILL_DIR/scripts/html2pdf-next.js" input.html --output output.pdf --width 210mm --height 297mm
   677→   677→   677→```
   678→   678→   678→
   679→   679→   679→0. **Full-Bleed CSS (MANDATORY)**: Every HTML file for Playwright PDF MUST include:
   680→   680→   680→   ```css
   681→   681→   681→   @page { size: 800px 1200px; margin: 0; }  /* CONCRETE values only - CSS variables NOT supported in @page */
   682→   682→   682→   html, body { margin: 0; padding: 0; width: 800px; height: 1200px; }
   683→   683→   683→   ```
   684→   684→   684→   **⚠️ @page rules do NOT resolve CSS variables** (`var(--x)` is silently ignored, falls back to A4). Always use concrete `px` values.
   685→   685→   685→   **⚠️ html/body must have explicit width + min-height** matching the canvas size. Use `min-height` (not `height`) so content taller than the design height expands naturally into a single long-page PDF.
   686→   686→   686→   **⚠️ Poster = seamless pagination.** When content exceeds `@page` height, `html2pdf-next.js` lets Playwright paginate at page boundaries - each page has the same dimensions, content flows seamlessly across pages (like scrolling a long image). Do NOT expand to a single oversized page.
   687→   687→   687→   `design_engine.py` handles this automatically via `override_css`.
   688→   688→   688→
   689→   689→   689→0.25. **Body Background for Multi-Page Mixed-Color Documents (MANDATORY)**:
   690→   690→   690→   When an HTML document contains multiple `.page` divs with **different background colors** (e.g. dark cover + white body + dark specs page), Playwright's sub-pixel rounding creates <1px gaps at `.page` edges where `body` background shows through. On dark pages, a white `body` = visible white edges.
   691→   691→   691→
   692→   692→   692→   **Fix: set `html, body { background }` to the document's darkest page background color.**
   693→   693→   693→
   694→   694→   694→   ```css
   695→   695→   695→   :root { --primary: #0f172a; }  /* darkest page color */
   696→   696→   696→   html, body {
   697→   697→   697→     margin: 0; padding: 0;
   698→   698→   698→     width: 210mm;                 /* match @page size */
   699→   699→   699→     background: var(--primary);   /* fills sub-pixel gaps with dark color */
   700→   700→   700→   }
   701→   701→   701→   ```
   702→   702→   702→
   703→   703→   703→   **Why this doesn't break white pages:** White `.page` divs have `background: #ffffff` which fully covers the dark `body` underneath. The dark body only shows through the <1px sub-pixel gap at the extreme page edge - imperceptible on white pages after anti-aliasing.
   704→   704→   704→
   705→   705→   705→   **Selection rule:**
   706→   706→   706→   - All pages same color → `body { background: <that color> }`
   707→   707→   707→   - Mixed dark + light pages → `body { background: <darkest page color> }` (dark edges on white pages are invisible; white edges on dark pages are the bug we're fixing)
   708→   708→   708→   - All pages white/light → `body { background: <lightest content bg> }` (e.g. `#f8fafc`)
   709→   709→   709→
   710→   710→   710→0.5. **No overflow:hidden + Browser Preview Adaptive Scaling (MANDATORY)**:
   711→   711→   711→   For fixed-size single-page designs (posters, infographics, certificates, etc.), **absolutely never** set `overflow: hidden` on `html`, `body`, or the main container. Reasons:
   712→   712→   712→   - When opening the HTML directly in a browser, the viewport is much smaller than the design size (e.g., a 1400px-tall page in a 900px viewport). `overflow: hidden` clips the bottom content and prevents scrolling.
   713→   713→   713→   - `html2pdf-next.js`'s pre-render check detects `scrollHeight > clientHeight` + `overflow: hidden` and triggers auto-fix (force-expanding the container), which may break the layout.
   714→   714→   714→
   715→   715→   715→   **`design_engine.py` handles this automatically**: During blueprint compilation, it auto-injects `@media screen` centering + scaling code, and the `html` background color uses `var(--c-bg)` matching the poster's main color. No manual addition needed.
   716→   716→   716→
   717→   717→   717→   **Correct approach when writing HTML manually**: Remove `overflow: hidden` and manually add `@media screen` scaling preview:
   718→   718→   718→   ```css
   719→   719→   719→   /* Fixed canvas size, no overflow */
   720→   720→   720→   html, body { margin: 0; padding: 0; width: 800px; height: 1400px; }
   721→   721→   721→   .page { width: 800px; height: 1400px; position: relative; }
   722→   722→   722→
   723→   723→   723→   /* Auto-scale to viewport in browser preview for full-page view */
   724→   724→   724→   @media screen {
   725→   725→   725→     html {
   726→   726→   726→       height: auto;
   727→   727→   727→       display: flex;
   728→   728→   728→       justify-content: center;
   729→   729→   729→       background: #0a0a1a; /* Surround color — must match poster's main background */
   730→   730→   730→     }
   731→   731→   731→     body {
   732→   732→   732→       transform-origin: top center;
   733→   733→   733→       scale: min(1, calc(100vw / 800), calc(100vh / 1400)); /* Consider both width and height */
   734→   734→   734→       margin: 0 auto;
   735→   735→   735→       box-shadow: 0 0 60px rgba(0,0,0,0.3); /* Optional: shadow to distinguish canvas in preview */
   736→   736→   736→     }
   737→   737→   737→   }
   738→   738→   738→   ```
   739→   739→   739→   `@media screen` rules only apply in browser preview; `page.pdf()` uses print media and is unaffected.
   740→   740→   740→   **Every fixed-size HTML must include this `@media screen` adaptive code.**
   741→   741→   741→
   742→   742→   742→0.75. **Page Container Overflow Clipping (MANDATORY for multi-page documents)**:
   743→   743→   743→   Every `.page` div MUST have `overflow: hidden`. Decorative elements (glow circles, gradient overlays) commonly use `width: 120%` or negative offsets - without clipping, they inflate `scrollWidth` beyond page width, causing Playwright to shrink all content and shift it left.
   744→   744→   744→   ```css
   745→   745→   745→   .page { overflow: hidden; }  /* Clips decorative overflow, prevents Playwright shrink */
   746→   746→   746→   ```
   747→   747→   747→   For horizontal flex layouts (≥3 items), always add `flex-wrap: wrap`. See `typesetting/overflow.md` §3.5.
   748→   748→   748→
   749→   749→   749→1. **Character Encoding Safety**: Never use Japanese kana (の, が, は), rare symbols, or Private Use Area characters in content strings. They corrupt to U+FFFD (�) during LLM→file write→read transit. Replace with plain Chinese equivalents: `の`→`之/的/缔/省略`.
   750→   750→   750→2. **Vertical Chinese Text** - When using `writing-mode: vertical-rl` for CJK, you MUST include:
   751→   751→   751→   ```css
   752→   752→   752→   writing-mode: vertical-rl;
   753→   753→   753→   text-orientation: upright;    /* Each glyph stands upright */
   754→   754→   754→   white-space: nowrap;          /* Prevent word-wrap breaking single chars to new column */
   755→   755→   755→   letter-spacing: 12px;         /* Typical CJK vertical spacing */
   756→   756→   756→   ```
   757→   757→   757→   Without `text-orientation: upright`, Latin/fallback fonts render rotated 90°. Without `white-space: nowrap`, CJK characters may wrap into unexpected multi-column layouts (e.g., 3 chars on one line + 1 char alone on next).
   758→   758→   758→3. **Font Coverage**: For CJK content via Playwright, always load Google Fonts Noto Serif SC or Noto Sans SC via `<link>` tag in `<head>` (NOT `@import` in CSS - `@import` must be the very first rule in a stylesheet or it's silently ignored). Example:
   759→   759→   759→   ```html
   760→   760→   760→   <link href="https://fonts.googleapis.com/css2?family=Noto+Sans+SC:wght@300;400;500;700;900&display=swap" rel="stylesheet">
   761→   761→   761→   ```
   762→   762→   762→   System CJK fonts vary across macOS/Linux - Google Fonts guarantee glyph coverage without relying on system fonts. `design_engine.py` already handles this automatically via `<link>` tag.
   763→   763→   763→4. **Post-Generation Text Verification**: After Playwright renders the PDF, extract text from every page and scan for `?` or `\ufffd`. If found, the source HTML has encoding-corrupted characters that must be replaced in the Python source.
